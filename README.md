# Flight Lookup Offline v1.8

아이폰·아이패드·Android·PC에서 사용할 수 있는 오프라인 편명 검색 PWA. 실제 DB는 GitHub Actions가 Virtual Radar Server standing-data(CC0)를 내려받아 구축합니다. 이 배포본에는 실제 전체 DB가 포함되지 않습니다. 예제 테스트 버튼은 3개 시연용 레코드만 표시하며 저장하거나 실제 DB로 간주하지 않습니다.

## 최초 설치 (GitHub 계정 필요, 공개 저장소 기준 무료)

1. https://github.com/new 에서 Public 저장소를 생성합니다. 이름 예: `flight-lookup`. README 자동 추가는 선택 사항입니다. 기본 브랜치는 `main`으로 사용합니다.
2. ZIP을 해제하고 내부 `.github`, `scripts`, `site`, `README.md`를 저장소 루트에 올립니다. GitHub 웹의 Add file → Upload files에서 폴더 구조를 유지하세요. Mac Finder에서 숨김 폴더 `.github`가 안 보이면 `Command+Shift+.`를 누릅니다. 웹 업로드가 숨김 폴더를 누락하면 GitHub 웹에서 Add file → Create new file로 `.github/workflows/pages.yml`을 만들고 제공 파일의 내용을 그대로 붙여넣습니다. ZIP 자체를 올리는 것이 아닙니다. 또는 GitHub Desktop/git을 사용합니다.
3. 저장소 Settings → Pages → Build and deployment → Source에서 **GitHub Actions**를 선택합니다.
4. Actions → Build and publish Flight Lookup → Run workflow → main → Run workflow. 성공하면 Settings → Pages 또는 Actions 배포 결과에 사이트 주소가 표시됩니다. 첫 실행이 Settings 설정 전 실패한 경우 다시 실행합니다. 자동 실행은 매일 한국시간 03:17 예정이며 GitHub의 큐나 정책으로 늦어지거나 중단될 수 있습니다. 60일간 저장소 활동이 없는 공개 저장소에서는 예약 워크플로가 비활성화될 수 있으므로 Actions에서 확인합니다.
5. 아이폰 Safari에서 해당 주소를 열고 첫 DB 다운로드가 끝날 때까지 기다립니다. 공유 → 홈 화면에 추가 → 추가. 홈 화면 아이콘에서 다시 열어 **오프라인 준비 완료** 표시를 확인합니다. 홈 화면 앱과 Safari의 저장소가 분리될 수 있으므로 반드시 홈 화면 앱에서 확인합니다.
6. 비행기 모드를 켜고 Wi-Fi도 끈 다음 앱을 완전히 종료하고 홈 화면에서 재실행합니다. 여러 편명을 검색해 확인합니다. DB 백업 버튼을 눌러 파일 앱의 '나의 iPhone'에 JSON을 저장할 수 있습니다. 백업은 DB만 포함하므로 앱 자체 캐시까지 복구하려면 온라인에서 앱을 다시 설치해야 할 수 있습니다.

## 사용

- KAL81, KAL081, KE81, KE081처럼 입력하면 정확히 일치하는 결과 우선. 정확히 일치하지 않으면 접두어 부분 검색. 항공사 코드만으로 검색도 가능.
- 숫자 뒤 알파벳이 붙는 콜사인도 원문 검색. IATA 환산은 원본 Number가 숫자 또는 숫자+문자일 때 항공사 IATA 코드와 조합. 실제 판매 편명·공동운항 번호와 일치하지 않을 수 있습니다.
- 복수 노선과 중간 경유 구간은 별도 표시합니다. 날짜별 실제 운항은 판별하지 않습니다.
- 앱이 열려 있고 온라인이면 마지막 성공 확인 후 5일~5일 12시간 경과 시 작은 버전 정보를 확인합니다. 내용 SHA-256 식별자가 변경된 경우에만 전체 DB를 다운로드하며 gzip 지원 환경은 압축 파일을 우선 사용합니다. 기존 DB와 저장소를 유지합니다. 수동 DB 업데이트 가능. 검색은 네트워크를 사용하지 않습니다. 백그라운드에서 자동 다운로드를 보장하지 않습니다.
- 새 DB를 검증한 뒤 IndexedDB에 하나의 트랜잭션으로 교체합니다. 오류·대폭 감소·구버전이면 기존 정상 DB를 유지합니다. 저장에 실패하면 기존 정상 DB를 유지하거나(없을 경우) 임시 메모리 모드로 표시합니다.
- 로컬 HTML은 화면 테스트용이며 DB 가져오기를 지원하지만 파일 URL에서는 브라우저가 저장소 접근을 제한할 수 있습니다. 실제 오프라인 홈 화면 사용은 HTTPS 배포가 필요합니다.

## 데이터 및 한계

Source: https://github.com/vradarserver/standing-data (CC0-1.0). Community-maintained reference routes, not verified flight schedules. 일부 편명과 항공사·공항 정보는 누락 또는 과거 데이터일 수 있습니다. 주요 항공사만 한글명을 표시하며 나머지는 영문명입니다. 실시간 위치·회항·목적지 변경·운항 여부는 확인하지 않습니다. 운항 판단용으로 사용하지 마세요.

## 개발 / 자체 서버

Python 3 표준 라이브러리만 사용합니다. upstream 저장소를 clone(airlines/schema-01, airports/schema-01, routes/schema-01 경로 포함)한 뒤 `python3 scripts/build_db.py upstream site` 실행. `site/`를 HTTPS 정적 서버에 배포합니다. `python3 -m http.server 8000 --directory site`로 localhost에서 개발 테스트할 수 있습니다. Service Worker를 수정하면 sw.js의 CACHE 버전을 올려야 합니다.

## 검증 범위

작성 환경에서 upstream 호스트 DNS 접속이 불가하여 전체 원본 DB 다운로드와 실제 GitHub 배포는 수행하지 못했습니다. 공개된 노선·공항 CSV 스키마에 맞추었고, 항공사 헤더는 여러 이름에 대응하도록 구성했습니다. JS 구문 및 합성 CSV 빌드·검색 인덱스 테스트를 실행했습니다. 실제 iOS 기기 테스트와 실제 전체 데이터의 완전성은 아직 확인되지 않았습니다.

## v1.0, v1.1 또는 v1.2에서 업그레이드
기존 저장소 루트에 이 업데이트 ZIP의 내부 `site`, `scripts`, `README.md`만 올려 기존 동명 파일을 교체합니다. `.github/workflows/pages.yml`, 아이콘, manifest 파일은 그대로 유지합니다. 기존 Workflow는 push 후 자동 실행됩니다. 기존 아이폰 홈 화면 아이콘과 IndexedDB는 삭제하지 않습니다. 온라인에서 앱을 다시 열어 v1.8 표시 및 DB 업데이트를 확인한 뒤 비행기 모드를 테스트합니다. 처음 v1.0 DB에서 이동할 때에는 버전 비교를 위해 1회 전체 다운로드할 수 있습니다. 서버는 계속 매일 빌드하며, 기기는 5일~5일 12시간마다 확인합니다. 실패 시 기존 저장본을 유지하고 자동 재시도를 늦춥니다.

## v1.2 모바일 검색 화면
입력창에 포커스가 있으면 폭 700px 이하 화면에서 상단 제목·DB 관리·상태 표시를 접고 검색 결과를 압축합니다. 검색창 옆 완료 또는 키보드 검색/Enter로 입력을 종료하면 일반 화면으로 복귀합니다. 키보드가 덮는 영역은 visualViewport를 통해 하단 스크롤 여유를 보완합니다. 검색 결과가 여러 개라면 스크롤하세요. 기존 IndexedDB 이름과 스키마, 5일~5일 12시간 갱신 및 원본 데이터 빌드는 v1.1과 동일합니다. 실제 iOS 키보드의 높이와 동작은 기기별로 달라 실기기에서 확인해야 합니다.

## v1.4 공항 검색
편명 검색은 유지합니다. 통합 검색창에서 IATA/ICAO 코드, 영문 공항명·도시명 및 주요 공항의 한글 별칭을 검색합니다. 공항을 선택하면 전체/출발/도착 등록 노선을 필터링할 수 있습니다. 경유 공항은 출발과 도착 양쪽에 포함될 수 있습니다. 전체 DB를 기기에서 조회하며 추가 API 호출이 없습니다. 모든 공항의 한글 명칭은 제공하지 않으며, 영문/코드 검색은 원본 공항 DB 범위에 따릅니다. 기존 저장소 및 5일 갱신 기능을 유지합니다. 공항 레코드의 선택적 다섯 번째 필드에 IANA 시간대를 추가합니다. 실제 운항일·운항 여부는 확인하지 않습니다.

## v1.4 통합 검색 및 현지시각
검색창 한 곳에서 편명 및 공항 코드/이름을 동시에 검색합니다. 정확한 편명 검색 결과를 우선 표시하며 공항 결과도 별도로 보여 줍니다. 공항 카드에서 현재 현지시각을 직접 확인하고 선택하면 전체/출발/도착 등록 노선을 봅니다. Airport local time은 현재 기기 시각을 공항 시간대로 환산한 것으로, STD/STA가 아닙니다. 시각은 15초마다 새로 계산합니다. IANA 시간대 규칙은 브라우저/OS 내장 데이터를 사용하므로 최신 iOS 및 정확한 기기 시계가 필요합니다. 시간대 정보가 없는 공항은 임의로 추정하지 않습니다.
서버 빌드 시 airportsdata CSV와 MIT 라이선스를 가져옵니다(https://github.com/mborsetti/airportsdata). ICAO 코드로 결합하며 명백한 IATA/국가 코드 충돌은 제외합니다. 출처와 라이선스를 DB와 배포 파일에 포함합니다. 다운로드 또는 검증 실패 시 빌드를 중단하여 기존 배포본을 유지합니다. 기존 Workflow 변경은 필요 없습니다. 최초 v1.4 설치 후 DB 업데이트 버튼을 1회 눌러 시간대 필드를 내려받으세요. 이전 DB에서도 편명 검색은 유지됩니다. 예정 출발·도착 시간은 원본 노선 DB에 없으므로 제공하지 않습니다.

## v1.5 아이폰 상단 흐림 개선
홈 화면 설치 앱의 세로 화면에서 시스템 상태 표시줄 아래에 여백을 확보합니다. 기존 검색 중 접히는 제목과 DB 관리 영역은 그대로 유지합니다. 상단 여백은 최소 82 CSS px이며 안전 영역이 더 크면 그에 맞춰 증가합니다. 일반 브라우저 및 가로 화면은 작은 여백을 적용합니다. 운영체제 자체의 스크롤 가장자리 효과를 직접 제거하는 것은 아니며 검색창을 그 영역에서 벗어나도록 설계했습니다. 기존 DB·갱신 주기·검색·시간대 로직은 변경하지 않습니다. 앱 캐시만 v1.5로 올립니다. iOS 실기기에서 확인이 필요합니다. v1.4에서 업데이트할 경우 DB 재다운로드는 필요 없습니다(서버 DB가 변경되면 기존 자동 갱신 정책에 따름).

## v1.6 현지시각 표시 개선
편명 결과의 양쪽 공항, 공항 검색 목록 및 선택한 공항 모두 Airport local time 표기를 사용합니다. 날짜(YYYY-MM-DD), 시각(HH:MM), UTC 시차 및 제목은 같은 작은 11px 일반 굵기·보조정보 색상으로 표시합니다. 시간 계산 및 DST, 15초 갱신, v1.5 상단 안전영역, DB 5일 자동 갱신은 변경하지 않습니다. v1.4 또는 v1.5에서 갱신 시 DB를 다시 내려받을 필요는 없습니다.

## v1.7 항공사 통합 검색
편명·공항 검색창에 항공사 이름(영문, 주요 한글 별칭), IATA/ICAO 코드 및 무선 콜사인 명칭 검색을 추가했습니다. 항공사를 선택하면 해당 항공사 코드로 등록된 노선만 표시하며 30개씩 더 볼 수 있습니다. 실제 운항편 목록이 아닙니다. 정확한 편명은 우선 표시하고, 강한 항공사 일치는 광범위한 공항 부분 일치보다 위에 표시합니다. 공항·항공사 코드 충돌 시 양쪽 결과를 유지합니다. 기존 DB에서 인덱스를 구성하므로 DB 스키마나 서버 빌드 변경, v1.6에서의 강제 DB 재다운로드는 필요 없습니다. 기존 워크플로와 홈 화면 아이콘을 유지하세요. 앱 캐시 버전만 v1.7로 변경했습니다.

검증: Chromium의 인라인 페이지 환경에서 시연 데이터와 630,294개 합성 노선으로 항공사 이름·코드·부분 일치, 항공사 선택·복귀, 편명 및 공항 검색, 코드 충돌 및 30개씩 추가 표시를 확인했습니다. 실제 iOS 및 배포 후 오프라인 재실행은 별도 확인이 필요합니다.

## v1.8 공항별 한국 항공사 우선 정렬
공항 카드 선택 후 전체/출발/도착 목록은 대한항공(KAL), 다른 한국 항공사(ICAO 코드 목록), 외국 및 기타 항공사 순입니다. 각 그룹은 항공사 코드 및 편명 순입니다. 국적 목록은 국내 항공정보포털과 항공사 코드를 참고하며 전체 세계 항공사에 국적 필드가 있는 것은 아닙니다. 동일 항공사·정규화 콜사인·동일 전체 경로만 중복 제거하며, 같은 편명의 다른 경로는 유지합니다. 출발/도착 구분은 등록 경로 기준입니다. 운항일/요일/STD/STA 필드가 없어 다음 운항편 2개씩 표시는 구현하지 않았습니다. 임의 시간이나 빈도를 추정하지 않습니다. DB 생성 및 스키마는 변경하지 않았으므로 v1.4 이상에서 강제 DB 재다운로드는 필요 없습니다. 앱 캐시만 v1.8로 갱신합니다.

검증: Chromium 인라인 페이지에서 합성 노선으로 세 그룹 정렬, 출발/도착 필터, IATA/ICAO 경로 중복 제거, 다른 경로 유지, 기존 편명 및 항공사 검색을 확인했습니다. 실제 iPhone과 배포 데이터는 미검증입니다.
